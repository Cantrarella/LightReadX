## 第 1 批 · 书库目录与外部文件

- [ ] **D1-1 下载目录入口显性化**
  改书库位置的能力**已存在**（`storage/tauri.ts` 的 `migrateLibraryTo` + 设置页 UI），但藏在设置深处。补：
  - 设置「存储」分区里显示当前书库路径 + 「更改位置」「在资源管理器中打开」
  - 下载页顶部也放一个入口（用户心智：下载的东西在哪）
  验收：能一键打开书库文件夹，能整库搬到 D 盘并重启后正常。

- [ ] **D1-2 外部文件即时读取（核心新功能）** —— 已定：**搬进 `books/<id>/`**
  用户往书库根目录直接扔 `.cbz / .epub / .pdf / .txt`，软件要能认出来并出现在藏书里。
  做法：启动 + 进入藏书页时扫根目录下「不在 `books/` 里」的散文件，走 `importNativeFile` 收进库，原名记进元数据（书名就用文件名，去掉扩展名）。
  - 收敛到现有导入链路，备份 / WebDAV 同步 / 阅读进度全不用改
  - 不做「原地引用」模式（避免和同步、文件被外部改名冲突）
  - 搬走后原位不再有文件，**UI 上要说清楚**（首次收取时提示「文件已移入书库」，或列表里标注「已收录」）
  验收：往书库根目录丢一个 cbz，进藏书页就能看到并打开。

- [ ] **D1-3 下载文件可见性**
  现在下载结果躺在 `books/<id>/content.cbz`，资源管理器里根本认不出是哪一本。
  方案：下载完成后按可读名另存一份到「下载目录」（`标题 - 章节名.cbz`），或提供「按标题命名的扁平目录」布局开关。

## 明确不做

- **API 域名自定义** —— 参考应用自己管网络层，我们走插件宿主，域名由插件负责。

## 风险与待确认

1. **移动端**：Android/iOS 沙盒没有「任意目录」，D1-1/D1-2 只能桌面端生效，移动端要降级（保留应用私有目录）。
2. **外部文件搬运（已定 A 方案）**：文件会从原位消失，必须在 UI 上说清楚，否则用户会以为文件丢了。首次收取时给一次提示即可。
3. **格式（已定不转）**：导出保留源格式，不做隐式转码。以后若真要批量转，再单独开一项，届时必须处理透明底铺白、动图降级。
4. **全速的代价（已定默认全速）**：并发拉满容易吃源站 429/403，靠「防封模式」开关兜底，而不是默认就限速。
5. **测试残留**：本地漫画里有一章《Vol.201 放课后の归路》（约 40MB）是验证时真下的，验收 D2-6 时正好当样本。
